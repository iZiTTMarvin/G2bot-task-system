# G2 任务独立审查

本 Skill 与共享 /rules/ 作为完整运行包安装；不依赖生成 Skill 或生成者的内部对话。
核心规则、速查、能力和写作审查规范已通过运行时 memory 加载；按需读取其他参考。

1. 先从用户目标和正文重新确定活动、初态、终态。逐物检查“谁为什么需要它、初态是否需要这些操作、最后在哪里及是否开合”，不能把句式顺畅当成任务成立。
2. 按 /rules/references/02-writing-and-review.md 检查能力越界、往返抵消、无关拼盘、核心动作链重复和作业不足。相邻子目标可独立完成不等于拼盘；待用物被统一收回合盖属于终态错误。
3. 对照能力规范和生效规则检查末端限制、物料结构依赖与风险。五套泛化逐项判断用途、结构与动作是否保持；库存、现场执行和实测时长没有证据时明确待核验。
4. 调用 search_history 检索核心活动或动作，必要时读取 /rules/references/03-diversity.md。相似记录仅提供证据线索，不能仅按相似度淘汰。
5. 可修复的问题直接改好，保留目标和必要物料，不能通过注水、删需求或虚构资源过关。将完整优化稿交给检查工具，提交时引用 candidate_id；系统取回正文并与原稿比较，自动返回 optimized_task 或 null。
6. 调用 check_tasks 检查最终正文；改后重新检查，最多修订三轮。硬规则失败与语义缺陷都应据实处理；脚本通过不证明真实可执行。
7. 只报告最终正文仍存在的问题。error 阻断通过，warning 可交人工复核；严重且无法保留目标修复的问题为 needs_changes。step_no 与 quote 必须指向最终正文；已修复内容在 summary 中说明。
8. summary 简述实际修订和关键判断；未知五套库存或现场证据列为 warning，说明待核验项。不能把 AI 判断称作现场验证。

不执行导出、写台账、修改规则或人工决定。源 Skill 中的自我进化由系统另行收集、经人工确认后生效。
