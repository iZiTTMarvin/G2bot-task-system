# 07 · 自我进化流程（用户对任务提出修改意见时读）

目标：用户说过一次的要求，之后每次出题都自动遵守；同时保持技能精简，不让规则越堆越乱。

流程分五步：**捕获 → 提炼 → 查重定级 → 落地 → 回归验证**。

## 一、什么时候触发（捕获）

本轮对话出现下列任一信号，就在**改完任务之后**走一遍本流程：

| 信号 | 例子 |
|---|---|
| 否定或纠正 | “不对”“不要”“别加”“这个做不了”“甲方不给过” |
| 打回原因 | 审核员或甲方打回的截图、批注 |
| 新的规范或物料信息 | 现场规范、机器人照片、物料清单、末端型号 |
| 审核通过的案例 | 通过截图（从中提炼写法，而不是照搬） |
| 明确的偏好 | “名字太单一”“多考虑点场景”“步骤再短一点” |

不记录的情况：只针对某一条任务的措辞微调（“第 3 步改成放到左边”）、一次性的出题数量或场景要求，以及无法复用到其他任务的意见。

## 二、怎么写（提炼）

每条写成**窄而可执行**的规则：“当 X 时做 Y／不做 Z”。不写“更认真一点”“更合理一些”这类空话。

必须带上：
- **规则**：一句话，执行者照着做就不会错。
- **原因**：用户为什么这样要求，用于以后判断边界情况。
- **来源**：日期，加上用户原话或截图摘要（证据），不编造。
- **落地**：这条规则写进了技能的哪个文件或脚本。
- **禁用词**（可选）：能用词语机械拦截的，列出词语。`validate_tasks.py` 会自动读取“生效”规则的禁用词并判为不通过。

## 三、查重与定级

先跑 `python scripts/learn.py add ...`，脚本会和已有规则比相似度：
- 字面高度相似：自动合并，该条命中次数加 1，并追加来源。
- 意思可能相近：脚本不写入，列出相近规则（退出码 2）。**由你判断是否同义**：同义就加 `--merge-into L-xxx` 重跑；确实是新规则就加 `--force-new` 重跑。用户换一种说法重复同一个要求，要靠这一步识别出来。
- 没有相近规则：直接新增，状态按下表定。

| 情况 | 状态 |
|---|---|
| 用户明确说出的要求或禁令 | **生效**（立即遵守） |
| 和旧的生效规则冲突，且用户最新的话更明确 | 新规则**生效**，旧规则改为**作废**并写明原因 |
| 证据互相矛盾（如审核通过与用户 SOP 冲突） | **待确认**，下次出题前问用户 |
| Agent 根据现象推断、用户没明说 | **候选**；命中 2 次或用户认可后升级为生效 |

## 四、落地（修改技能本身）

规则生效后，按影响面放到对应位置，**不要所有东西都堆进 SKILL.md**：

| 规则类型 | 写到哪里 |
|---|---|
| 每次出题都要遵守的硬约束（手数、步数、命名） | SKILL.md 核心原则，一句话 |
| 夹爪或机器人能力、场景约束 | references/01-capability.md |
| 步骤写法、措辞 | references/02-writing-and-review.md |
| 场景发散、去重 | references/03-diversity.md |
| 新的通过案例或反例 | references/04-examples.md |
| 能用词语拦截的 | 在规则里写“禁用词”（脚本自动生效），或改 validate_tasks.py |

落地后在规则的“落地”一栏写清位置，并在技能根目录 `CHANGELOG.md` 记一行。

## 五、回归验证

同一轮对话里用户连续提了多条意见时，先逐条改好任务，攒到最后一次性记录规则和跑下面的检查，不要每条意见各跑一遍。改动技能或脚本后要跑：

```bash
python scripts/learn.py check        # 规则体量、待升级候选、未落地规则
python scripts/regression.py         # 通过案例必须过，已知坏例必须被拦下
```

规则能被脚本检查时，在 `assets/regression_cases.csv` 加一条对应的坏例，防止以后改技能时把它改丢了。

## 六、保持精简

- “生效”规则超过 30 条，速查 `06-brief.md` 超过 5500 字符，或 SKILL.md 超过 90 行时，`learn.py check` 会提醒，需要做一次合并：同类规则合成一条，已经完整写进正文和脚本的规则保留编号但缩成一行。
- `06-brief.md` 由 `learn.py` 自动生成，出题前读它；不要手改，手改完整库后运行 `python scripts/learn.py brief`。
- 规则不按时间过期；只有当用户改口、物料或设备变化时才改为作废。
- 只记规则，不贴整段对话或整条任务。

## 七、对用户透明

本流程走完后，在回复末尾用一两句话告诉用户记住了什么，例如“已记住：订书机这类需要大力按压的工具不出题（L-004）”。用户说“不用记”或“记错了”，就把这条改为作废，或者直接删掉。
