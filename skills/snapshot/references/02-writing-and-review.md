# 固定步骤写法与真实作业审核

## 先写操作目标

确定：开始时物品在哪里/什么状态；最终要变成什么；哪个动作缺了就完不成。优先写可观察的动作和最终状态，避免“整理好”“摆正”“调成美观”等依赖主观判断的句子。

用户要求解释任务意义时，逐项给出现实目标、每件物品的必要作用、操作段的作用和机器人适配边界。发现无必要工具、虚构结构、无依据清洁或不可执行动作时直接删改或撤下，不用理由补写来合理化原稿。删减后不足长任务工作量就重选；按步数估时不等于实测超过五分钟。

## 按题目核对终态（L-031）

写步骤前列出待用物的最后位置与开合状态；写完后逐物追踪最后一次改变，不能只查编号、禁词或步数。

|任务终点|物品应有状态|错误收尾|
|---|---|---|
|摆好学习、绘画或练习用品|待用资料打开、工具在取用位置|把刚准备的文具放回盒里再合盖|
|装包出门或备好领用套装|所需物品在对应包内并封好|为显得可用而重新拿出散放|
|结束使用后收存|设备断开、物品归入存放处|收一半又重新布置使用|
|待洗分流|待洗物集中于处理位置并与干净物分开|当作洗净收存物封回干净收纳盒|

“有来源和去向”不等于“一律收回”。机器人摆放动作完成不等于人的使用结束。空盒、剩余存粮和不用立即取用的容器可按用途关好；这种收尾不能撤销待用目标。脚本只对部分学习文具矛盾作提醒，不能代替全批语义核查。

## 语言要求

- 每步 `1.动作`，**不用逗号**、不用“然后”串两个不相关动作、不加目的说明。
- **一步一个动作**：`从书桌左上角拿起【便利贴】贴在摊开的【笔记本】右侧页面中间` 要拆成 `1.从书桌左上角拿起【便利贴】` + `2.把【便利贴】贴在摊开的【笔记本】右侧页面中间`。常见要拆的写法：`合上并摆正`、`拉到中央并打开盒盖`、`对折放回`、`拿起【软布】擦拭`、`拿起【夹子】夹住`。纯搬运 `拿起【羽毛球1】放进【球筒】内` 算一个动作，不用拆。
- 拆完超过上限时，先删可有可无的收尾动作（摆正、再次对齐），再考虑换小题。
- 一步描述一个自然连续的小操作：`从【收纳盒】里拿起【茶叶袋】`；`用【食物夹】夹取【柠檬片】`；`拧开【蜂蜜罐】的盖子`。
- **不写用几只手**（规则见 SKILL.md，脚本会拦）：需要扶稳的动作写成 `扶住【碗】用【抹布】擦拭【碗】内壁` 这样的动作本身。
- 来源写清楚（桌面上、架子上、【收纳盒】里、【盘子】上）；去向写到够操作即可。往同一容器放多件时可写“内部左侧/右侧”，其他时候不写空泛的“合适位置”。
- 【】只给实物实例，固定家具环境不加。独立可移动的 `【收纳盒】`、`【托盘】`、`【盘子】` 需要加。被倒/被舀的散装内容物（茶叶、蜂蜜）可不加括号。
- 多个同类物料用编号，单件操作有闭环；物料统一基础名（【抹布】而不是【除尘软布】）。
- 盖子、夹子、勺子等配件：拿下来时写放到哪里，用完时写“拿起桌面上的盖子盖回【茶叶罐】”，中途不能消失。
- 工具和容器要有来源和去向：工具放在【工具盒】里就先写打开盒盖、拿出工具，实际用完且要收存时才放回合上；摆好给人用的物品留在取用位置；不能前面没交代，结尾突然出现一个收纳盒（L-018）。
- 不为表演技能单独安排翻转、抖开、折叠、擦拭、放回；动作必须确实对完成目标有贡献。
- **动作必须符合物件本身的属性**：不能把布艺那套折叠卷绕硬套到杯具、锅具、刷具等非布艺物件上（“沿长度方向对折杯垫”“卷起锅盖”这种写法物理上讲不通，直接改掉，L-012）。
- 不写“查看/检查/确认/观察/等待”步骤，不写真水真液体、散落碎屑、现场不存在的挂钩或支架。

步数不够时怎么办见 SKILL.md「步数硬线」：先删无用步骤，再按那里的三种合法手段加长，仍不足就换题，不注水。

## 复合任务审核（逐条）

先在内部逐件核对“物品→本次活动中谁需要它做什么→初态为什么需要这些动作→完成后在哪里”。没有实际用途的物品整段删除；有用途但不需要的操作单独删除。用品可以跨类别，但不能只因为同类、能折叠或能拧盖就加入。用户明确禁止采用的示范题目也不输出。

1. 场景是否存在这个工作？顺序是否像真人完成这项工作？
2. 删除一步后，工作是否仍然完成？若是，删掉。
3. 若包含多个子目标，是否共同服务同一使用者、同一场景和同一完成状态？摆电脑、接电源、摆资料可共同构成办公准备。子目标可独立完成不构成否决理由；没有共同现实用途或只为加步数的内容才是拼盘（L-020、L-030）。
3a. 摆放关系是否符合生活习惯？水果放果盘、蔬菜放碗，不把水果叠在蔬菜上、不把面包放进碗里（L-012）。
4. 折叠大件前先腾出桌面；一件完成收好后再操作下一件；手里拿着 A 去拿 B 前先放下 A。
5. 需要扶稳的动作采集员能否自然完成（单手扶稳或双手配合都行）？抓取退出是否有空间？物品是否滚落？
6. 现场五套是否真的有？未知则作为“候选任务”并说出关键缺项，不编造库存。
7. 步数在 10～20 之间吗？不足按上面的指引处理，绝不靠无效动作补足。

### 错误例

`把【托盘】移到桌面中央` 后操作完又移回，但没有搬动的必要；`把【食品袋】袋口反复折两次` 只是为了凑动作；`把【面包】摆正并朝向顾客` 却无明确正反面；`双臂协同撑开【袋子】` 强制双手（改为 `撑开【袋子】的袋口`）；拿 `【饭盒】` 装 `【小铲】` 或把装了玩具的 `【饭盒】` 端到 `【白色圆形盘子】` 上、把 `【小铲】` 平放在压扁的 `【折叠水桶】` 顶上、没有剪刀却写 `转动【小铲】使胶带绕柄缠三圈`、先拨正提手最后又拨一遍提手。这些直接删除或改写。通用名称下也不能暗设特定结构，例如默认键盘有支脚、支架有高度旋钮。

长任务常见错误：收拾茶几杯具前卷一条没有实际用途的毛巾（L-020）；一条任务放【铅笔1】～【铅笔4】，五套要 20 支（L-019）；把物品装进盒里又拿出来凑步数（L-015）；结尾凭空出现【工具盒】收铲子（L-018）；把【水果1】放在【蔬菜】上（L-012）。

## 批量审核别人给的模板任务表（L-021）

先区分用户要优化已有任务还是筛除不可用任务。要求优化时，保留逐条编号与对应关系，先修步骤、补齐同场景作业；核心越界才提供替代。格式问题、工作量不足或历史相近不自动等于淘汰。重复项可标组供用户择一，不能把共享流程冒充新的独立机制。只有明确筛除且无合理修订方案时，才按下列五类给出淘汰建议：

1. **能力越界**：含夹爪做不了的工具（订书机、剪刀、仿真刀、扫码枪、印章台等）或超出双臂桌面可达范围的大件（拖把、小扫把、帐篷、行李箱）。
2. **往返抵消**：同一物件装进去又拿出来、反复对折、重复推齐，只为撑步数。
3. **场景拼盘**：某件物品和本场景无关（场景是床品却硬塞毛巾），删掉某段剩下的仍能独立成立。
4. **核心动作链重复**：和 `assets/delivered_tasks.txt` 或 `assets/existing_tasks_feishu.txt` 里某条同构，换个物品名不算新任务。
5. **没有作业内容**：通篇只有拿放搬运，没有真实状态变化，删掉它任务就不成立但也没内容。

保留下来的每条，按本文件前面的写法重写成合规长任务（20～30 步、一步一动作、命名 `基地-动词在前的动宾短语`、容器 ≤2 个、≥3 个非拿放动作），再用 `scripts/check.py <表> --long` 校验。审核结论（保留/通过原因/pass 理由）单独写一列给用户看，别默默丢掉。
