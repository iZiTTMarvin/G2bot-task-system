# 固定步骤写法与外部任务表审查定稿

## 一、按题目核对终态（L-031）

写步骤前列出待用物的最后位置与开合状态；写完后逐物追踪最后一次改变：

| 任务终点 | 物品应有状态 | 错误收尾 |
|---|---|---|
| **摆好待用**（学习/品鉴/陈列/促销） | 待用物留在取用或展示位置 | 把刚摆好的物品又收回盒里合盖 |
| **装包携带 / 备好礼袋** | 所需物品在包/袋内并封好（或立好待提） | 装好后又重新掏出散放 |
| **结束使用后收存**（打烊/换季） | 物品归入存放容器并合盖/拉上拉链 | 收一半又重新摆出展示 |
| **集中待洗 / 回收空瓶** | 待洗物或空瓶集中于回收筐/待洗篮 | 当作干净待用物封回普通收纳盒 |

## 二、正规机器动作 vs 拟人化修整动作（L-027）

步骤是给现场采集员看、由 G2 双臂平行两指夹爪执行的，必须保持朴素、正规、直观：

| 类别 | 正规写法（推荐） | 拟人化/机器不可做写法（一律删除或改写） |
|---|---|---|
| **取放与陈列** | `拿起桌面上的【酒瓶1】`、`将【酒瓶1】放到样品架的上层` | `扶正歪靠的【酒瓶1】`、`转动【酒瓶1】让标签朝向前侧`、`将【烟条1】竖插进上层` |
| **袋类操作** | `拿起桌面上的【礼品袋1】`、`撑开【礼品袋1】的袋口`、`将【礼盒】放进【礼品袋1】里` | `将【礼品袋1】的提手竖起`、`将【礼品袋1】的提手分开`、`将【礼品袋1】的袋身抚平` |
| **盒/箱/罐开合** | `打开【礼盒】的盒盖`、`合上【礼盒】的盒盖`、`拉开/拉上【收纳袋】的拉链` | 对原本已封口的样品罐空写 `拧紧【零食罐1】的罐盖`；`扣好箱盖的卡扣`、`翻开/折回【纸箱】的摇盖` |
| **布艺操作** | `将【桌布】放到促销台中央`、`将【桌布】展开铺平`、`将【抹布】对折`、`将【抹布】放到桌面后侧` | `把【桌布】的左前角/右前角压平`、`将【方巾1】的四角向上包起`（包裹酒瓶）、`将【抹布】搭在桌角/边沿` |
| **擦拭部位** | 有真实清洁需要时，明确对象和脏污，如 `用【抹布】擦去桌面的灰尘` | 没有脏污或清洁理由就擦；过度细分：`擦拭【酒瓶1】瓶身`、`擦拭【礼盒】内底`、`擦拭【烟灰缸】内壁/边沿` |

## 三、外部任务表清洗与多表合并定稿 SOP（L-010/013/021/027）

当用户提供 1～N 份外部或不同 AI 生成的任务表要求“审查、去拟人化、合并定稿”时，按以下 4 步一次性完成：

修订长任务先读 `04-examples.md` 的「长任务模板」，保留原表的合理作业量；步数按 SKILL.md 核心原则 4，不设默认上限。删除难动作后补同场景必要作业，不靠删收尾或合并独立动作压缩长度。步数不能证明现场时长。

### 第 1 步：识别问题并逐条修订
扫描所有输入任务，识别以下 5 类问题。优化请求保留逐条对应，优先修订或提供同场景替代；只有用户要求筛除且无法修订时才建议删除。

不要按工序族只留一条代表任务来替代整批改写。可共用执行方案，但保留可修订的原任务记录及编号；分别报告原记录数量、方案数量和独立去重数量，不把同方案的场景复用当成更多独立新任务。
1. **能力越界**：核心动作依赖平行夹爪做不了的操作（如 `将【方巾】四角向上包起` 包裹酒瓶、使用剪刀/订书机/扫码枪）。
2. **物理自相矛盾**：如对已拉好拉链的自封袋再用夹子夹封，或上一步 `用【夹子1】夹住袋口`、下一步又写 `将【夹子1】放到桌面左侧`。若能与另一条半成品任务互补，则**二合一**保留。
3. **同批任务重复**：按 `03-diversity.md` 和 SKILL.md 核心原则 4 比较有效步骤；允许50%重复，不因同名、同物料或原子技能相同直接淘汰。默认不逐条比对历史台账。
4. **场景脱离**：与当前主题场景明显无关的硬凑任务。
5. **剥离伪动作后无实质作业**：删掉 `抚平袋面/扣卡扣/转标签` 后只剩纯拿放且无法合理扩展的任务。

### 第 2 步：批量剥离拟人化动作与规范化命名（2026-10-30 新规）
- **步骤清洗**：按上方对照表删掉全部转标签朝向、理提手、抚平袋面、四角包折、空拧盖、扣卡扣、折纸箱摇盖、抹布搭边角，将细分擦拭统一为 `擦拭【XX】表面`，将细化禁词替换为通用基础词（`茶杯/咖啡杯` → `杯子`）。
- **名称清洗**：按 SKILL.md 的命名规则保留基地和动宾主干；如 `嘉兴数采-铺平并叠好短裤` 可改为 `嘉兴数采-铺平折叠短裤` 或 `嘉兴数采-折叠短裤`。必要的工具、场景、来源可在动词前说明，不把改名当成删步骤。

### 第 3 步：按完整工作展开步骤
- 单条任务内部采用 `拿起【物品1】 → 操作【物品1】 → 放置【物品1】` 的自然穿插顺序；
- 打开盖子与放下盖子、取物与后续操作分别写；不拆伸手、靠近等控制细节。
- 工作量不足按 SKILL.md 核心原则 4 处理；重复作业须有真实数量需求，不能为增加技能标签或长度拼物品。

### 第 4 步：一条命令补物料、校验并导出 xlsx
```bash
python scripts/check.py 草稿.md --long --fill-materials --export 定稿任务表.xlsx
```
完成脚本检查及清洁依据、用途、终态和同批近似任务复核后（见 `03-diversity.md`），向用户交付；不自动追加历史台账。

用户提供参考工作簿时沿用其表格边界。原表有横竖细实线的，交付文件给实际单元格设置四边边框；底色、隔行色和工作表网格线不能代替边框。用户要求纯任务库时不添加评估结论页。

任务库全部编号步骤放在同一个单元格，格内每行严格一个步骤，禁止每行两步或多步并排；不得为控制行高把步骤拆到多个单元格。长任务增加任务格的显示高度，必要时将该任务对应的各列分别纵向合并为完整单元格；步骤原文只写入一个锚点，格内不留步骤分隔线。检查最长条目的完整显示，不截掉后半段或缩小到难以阅读。
