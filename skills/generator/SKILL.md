# G2 任务生成

本 Skill 与共享 /rules/ 作为完整运行包安装；共享规则来自指定上游，不能脱离该运行包单独安装。
核心规则、速查、能力和写作审查规范已通过运行时 memory 加载；按需用 read_file 读取其他参考。

1. 先确定一次具体活动、使用者、初态和终态。逐件说明物料在活动中的实际作用，排除只为凑步数的物品、特殊结构和未经证实的库存。
2. 用 search_history 按活动或核心操作检索，命中只是线索。读取 /rules/references/03-diversity.md，比较整条动作链及连续核心段；不靠换标题或物品名避重。
3. 从初态顺序推演完整操作。逐物追踪位置、开合与工具去向；待用物留在取用位置。允许服务同一活动的相邻作业，子目标可独立完成不等于拼盘。
4. 删掉不影响完成的操作，再检查工作量。一般任务和长任务以本次输入范围为准；不足就重选工作量足够的题，不能拆碎自然拿放或反复搬运。
5. 对核心物料逐项考虑五套常见变体：用途、结构、抓取条件和动作是否保持。数量存在不证明可泛化；未知库存和夹爪、可达、时长缺少现场证据时保留待核验事实。
6. 用 derive_materials 汇总步骤中的实物实例。完成整个批次后调用 check_tasks，结合硬规则、历史近似及批内重叠线索修订；改后重新检查整个最终批次，最多修订三轮。
7. 通过检查返回的 candidate_id 提交选定的完整草稿，系统取回正文，避免重抄引入差异。脚本通过不能替代真实用途、终态与五套泛化判断。只在无法消除的问题上保留真实缺口，交给独立审查和人工复核。

按人工反馈重写时保留原目标及反馈未要求改变的合理部分；重写后执行同样的检查。
需要范例才读 /rules/references/04-examples.md；批量多样性、物料和标签说明见 /rules/references/05-batch.md。
本运行包由后端提供结构化提交、版本、导出和人工裁决；不执行源 Skill 中的聊天交付、台账回写或自我修改。
