# G2 任务系统

本地 G2 遥操作采集任务生成与审核系统。后端使用 FastAPI + SQLite + Deep Agents，前端使用 React + Vite + shadcn/ui + AI Elements。

## 启动

Windows 已安装 Python 3.12+ 和 Node 20+ 后，在 PowerShell 中运行：

```powershell
.\start.bat         # 正式模式，使用已配置的 OpenAI / Anthropic 兼容接口
.\start.bat demo    # 本地演示，使用后端 FakeModel
.\start.bat dev     # 开发模式，前端 5173、后端 8000
```

访问 <http://127.0.0.1:8000>。启动时检查并安装当前依赖；正式模式和演示模式每次启动都会构建当前前端，构建失败不会启动服务。

如果 8000 已被占用，可以在启动前设置 `$env:G2_PORT = '8001'`，随后运行 `.\start.bat` 并访问对应端口。每个数据目录只能由一个服务实例使用；使用备用端口并行测试时，还需要通过 `G2_DATA_DIR` 指定独立数据目录。正常关闭时会等待当前后台作业结束，避免另一实例过早接管数据。

## 使用

界面是**双 Agent 工作台**：左侧选择任务集，主区描述需求；产生任务后展开结果区。窄窗口通过「对话 / 任务结果」切换，导航可以收起；支持浅色、深色及系统主题。

1. 在「模型设置」选择 OpenAI 或 Anthropic 兼容格式，填写服务地址、API Key 和模型；可独立设置审核模型，留空时沿用生成模型。
2. 新建生成任务集，上传物料库（TXT/MD/CSV/XLSX）或直接说要做什么。没有物料库也可生成，现场库存需逐项核验。当前资料会随继续生成继承，支持替换、追加、清空；CSV/XLSX 物料可查看结构化预览。
   条数由 Agent 按实际需求和可用物料决定。常规任务参考 10–20 步；长任务以现场工作量为目标，优先 30 步以上，时长须实测。
3. Agent 回复里会写明生成了几条、哪几条需要人工处理，任务同时出现在右栏。
4. 右栏勾选任务点「送审」，自动切到「审核 Agent」会话：它按 Skill 逐条审、能改的直接改，回复里说明改了几条。
5. 点任务进入详情，查看正文、AI 审核意见和版本变化，直接编辑步骤与物料。人工核验需逐项勾选，可填写一份共用依据，也可展开单项补充；依据会按当前核验项分别保存，模型不会代填或代确认。
   同批任务存在相似线索时会显示「相似待留意」，不影响人工确认；步骤完全相同则需先调整。
6. 勾选后可「导出草稿」（任意状态）或「导出交付」（当前版本已人工确认且核验完整）。表格带「状态」和「审核意见」列；跨批选择需先调整。

审核 Agent 也可以单独用：粘贴一段任务文本（每行一步，物料用【物料名】标注）或上传文件，它就按 Skill 改。
所有消息都留档，全部用户要求、最近回复、当前资料和任务摘要会进入下一次生成；上下文超限时明确提示，不静默丢弃要求。

发送请求失败时保留输入与附件；成功入队后清空本次输入。后台模型失败时保留消息、资料与已生成任务，同一作业只展示一处错误，可展开技术详情、检查模型设置或重试原请求。
已生成的任务不会因为失败而丢失，可以单条「重新审核」。

前端只连接真实后端 `/api/v1`，不包含 Mock 数据或 Mock 控制台。

## 开发验证

```bash
cd backend && .venv/Scripts/python -m pytest
cd frontend && npm run typecheck && npm run lint && npm run build
```

前端状态与步骤 Diff 回归使用 `cd frontend && npm test`（需要 Node 的 TypeScript strip 支持，本次验证环境为 Node 22.20）。界面重构的截图、交互检查及验证边界见 [UI 架构重构验收](docs/UI架构重构验收.md)。

后端单独启动：

```bash
cd backend && .venv/Scripts/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

目录：

- `backend/`：API、生成与审核作业、SQLite、Deep Agents 运行入口、规则工具和测试。
- `backend/app/services/conversations.py`、`chat.py`：会话与消息层（把一次性作业包装成可对话的工作台）。
- `frontend/`：响应式工作台（任务集导航 / 需求与执行反馈 / 按需展开的任务结果）。
- `skills/snapshot/`：从指定 `.agents` 上游导入的规则、脚本与资源。
- `skills/generator/`、`skills/reviewer/`：两个独立角色的 Skill，共用领域规则。
- `data/`：本地数据库、附件、导出文件和模型配置。
- `docs/`：当前行为契约与历史设计资料，`openapi.json` 为当前请求结构（0.3.0）。

## 概念

- **会话（conversation）**：一个人话工作和一组任务的容器。两个 Agent 各有自己的会话列表。
- **批次（batch）**：后端容器，一个会话可以有多批；名称取用户第一句话，不再由模型命名。
- **任务（task）**：真正交付的东西，带完整版本链（AI 首次生成 / AI 审核优化 / 人工编辑）。
- **四态**：生成中 → 审核中 → 待确认 → 已确认。原来的 7 个内部状态仍保留在库里，界面只露这四态。
- **导出**：草稿允许任意状态；交付要求当前版本有有效人工确认和完整核验记录。

正式模式由两个独立 Deep Agents 实例完成生成和审查，支持按需读取 Skill 参考、物料汇总、单任务检查、同批对比及有限修订。生成和改写不检索历史任务库。运行方式、规则更新、执行证据及验证限制见 [Deep Agents 实现说明](docs/DeepAgents实现.md)。

当前业务边界、旧库升级、物料模板、状态转移、规则维护和只读统计命令见 [当前行为契约](docs/当前行为契约.md)。版本历史支持查看和复制旧稿为新人工版本，原记录不覆盖；未保存编辑关闭时会提示。
