# 改版说明 v0.2（双 Agent 工作台）

本次改动针对"系统难用"的六条具体问题，核心是把**填表单 → 看列表 → 进抽屉**的流水线，
改成**跟两个 Agent 对话 → 右边出结果 → 在线改 → 导出**的工作台。

接口契约版本从 0.1.0 升到 0.2.0，`docs/openapi.json` 已重新生成。

---

## 一、六条逐条对照

### ① 去掉"几条"和"多少步"

| | 改之前 | 改之后 |
|---|---|---|
| 界面 | 输入框右侧一个数字框「3 条」+ 一个下拉「10–20 步 / 20–30 步」 | 全部删掉，只留上传物料库/附件和一句要求 |
| 请求 | `task_count` 1–10，`task_mode` `standard`/`long` | `task_count=0`（由 Agent 决定）、`task_mode=auto` |
| 校验 | `len(tasks) != task_count` 直接报 `MODEL_PROTOCOL_ERROR` | 只在显式指定条数时才校验；`auto` 步数区间 10–30 |

关键点：**只删界面会炸**。`deep_agent.generate_batch` 原来硬校验条数，所以后端一起改了：
`prompts_spec.STEP_RANGES` 增加 `auto: (10, 30)`，系统提示改成"条数以上传物料库能支撑几个互不重复的活动为准，不要凑数"。

代码：`frontend/src/components/ChatPanel.tsx`、`backend/app/services/chat.py:_generate`、
`backend/app/agents/deep_agent.py`、`backend/app/agents/prompts.py`。

### ② 两个 Agent 各有一个对话框

新增会话层：

- `conversations(id, agent_role, title, created_at, updated_at)`
- `messages(id, conversation_id, role, content, batch_id, run_id, attachments_json, task_ids_json, created_at)`

左栏按 Agent 分成两组会话，中间是对话，每条消息带时间、附件、作业进度。
**每次 Agent 回复对应一次真实作业**（`generate_batch` / `review_batch`），失败有明确错误码，
不会出现"聊得很热闹但什么也没做"。历史消息会拼进下一次生成的 `reference_text`，所以"接着说"是有效的。

代码：`backend/app/services/conversations.py`、`backend/app/services/chat.py`、
`frontend/src/components/ChatPanel.tsx`、`frontend/src/App.tsx`。

### ③ 生成后点"送审"，另一个 Agent 开工

- 右栏勾选任务 → 「送审」→ 自动切到审核 Agent 会话，并留下一条可追溯的消息。
- 后端新增 `review_batch` 作业：一个作业占住整组任务，逐条审核、按条推进度，单条技术失败不拖垮整批。
- 审核结果：能修的直接写入新版本（`author_type=ai_revision`），并在回复里说明改了几条。

代码：`backend/app/services/runs.py:start_review_batch / _execute_review_batch`。

### ④ 审核 Agent 可以独立用

三种入口都支持（这是你选的"三种都要"）：

1. **从任务库勾选**：右栏选任务送审，保留版本链和 diff。
2. **粘贴任务文本**：每行一步，行首编号自动去掉（`1.`、`2、`、`第3步`、`4)` 都认），物料从步骤里的【物料名】自动推导。
3. **上传文件**：TXT/MD/CSV/XLSX 解析后走同一条粘贴通道。

粘贴/上传会建一条"导入待审"任务（不经过生成模型），所以审核结果同样有版本、有导出。

代码：`backend/app/services/conversations.py:parse_pasted_task`、`frontend/src/components/ChatPanel.tsx`（粘贴弹窗）。

### ⑤ "居家桌面任务集"这类分类

原因找到了：`batches.name` 被模型返回的 `name` 直接覆盖（`UPDATE batches SET name=?`），
所以每次叫法都不一样、也没法改，它根本不是分类。

现在：

- 批次名固定取**用户第一句话前 24 字**，生成后不再被覆盖；
- 界面上不再出现"任务集"这一层，入口改成**会话**（标题也是第一句话）；
- 模型起的 name 只作为一句话写进 Agent 回复（"模型起名：xxx"），不参与导航。

代码：`backend/app/services/batches.py:create`、`backend/app/services/runs.py:_execute_generate_batch`。

### ⑥ 人工审核 = Agent 审完 → 在线改 → 导出

- **状态压成四态**：生成中 / 审核中 / 待确认 / 已确认（+ 需处理）。原来 7 个内部状态仍存库里，界面只露这四个，
  不会再出现"全都是待人工审核"。
- **在线编辑放开**：原来 `approved` 之后 `canEdit=false` 彻底锁死；现在任何未被作业占用的状态都能改，
  改完自动退回「待确认」（避免"改完还算已确认"的假象）。
- **导出不再要求 approved**：任意状态都能导，表头变成
  `任务名字 | 任务步骤 | 单套所需物料 | 状态 | 审核意见`，审核意见含 AI 结论和未解决问题清单。

代码：`backend/app/services/tasks.py`、`backend/app/services/exports.py`、`backend/app/services/render.py`。

## 二、另外加的三件事

1. **AI 改了什么（diff）**：任务详情里对比当前版本和上一版，`+新增 / −删去` 逐条列出。
   原来只能看最终版，等于闭眼信任 Agent。
2. **审核意见与步骤对应**：每条意见标出第几步、必改还是建议、以及建议动作。
3. **版本号可见 + 可回滚基础**：详情里显示 `v3`，版本链在库里完整保留（回滚 UI 还没做）。

## 三、这次刻意没做的

| 没做 | 原因 |
|---|---|
| 真正的连续推理对话（Agent 记住你上一轮说过的话并自己追问） | 现在每次调用都是新 `thread_id` + `InMemorySaver`。要做持久化 checkpointer，属于独立一轮改造，且会动 Deep Agents 版本依赖。当前用"消息历史拼进上下文"过渡，效果够用但不等于真记忆。 |
| 物料库升级成独立实体（可命名、可复用、多套） | 现在仍是附件文本 + 分析，左栏只做了列表展示。要做成实体要加表和一套管理界面。 |
| 重复度前置到任务卡片 | `check_tasks` 内部有 overlap 检测，但结果没有回传到任务字段，需要改 Agent 输出契约。 |
| 导出列可配置 | 现在固定 5 列，够用；要可配得加导出模板。 |
| 版本回滚按钮 | 数据和 API 都在，差一个入口。 |

## 四、验证情况

- 后端测试：**92 个全过**（原有 86 个 + 新增 `tests/test_conversations.py` 6 个）。
  三处旧断言按新语义更新：批次名不再被模型覆盖、通过后仍可编辑（退回待确认）、导出允许未通过任务。
- 前端：`tsc --noEmit` 通过，`npm run build` 通过（2 条 React Compiler 风格告警，无 error）。
- 演示模式端到端跑通：建会话 → 发言 → 生成 3 条 → 送审 → 审核 3 条 → 粘贴 1 条审核 → 导出 5 列 xlsx。

## 五、数据兼容

`db.init_db()` 里加了轻量迁移：只给旧库 `ALTER TABLE batches ADD COLUMN conversation_id`，
不改既有数据。旧数据可以直接用，只是旧任务不会出现在任何会话里（会话列表为空，右栏为空）。
换数据目录或删 `data/` 可从头开始。
