# G2 Demo 前后端接口契约

> 契约版本：0.1.0，2026-10-28。设计基线，尚未实现。
> 字段、枚举、必填与响应结构以 [openapi.json](./openapi.json) 为准；本文件定义执行语义、状态约束和前端交互。

## 1. 两端如何开工

后端负责人维护 OpenAPI，前端据此维护 API 层与 mock。前端不需要等全部接口实现；双方先接通健康检查、任务列表、任务详情、保存、通过和驳回，再接真实生成与审核。

后端实施后导出实际 OpenAPI，与本契约逐项核对。文档中的 JSON 是业务示例，不等于已有服务响应。实际框架生成的验证错误必须适配为下面约定的错误结构，不能直接泄漏另一套 422 格式。

所有路径以 `/api/v1` 为前缀，前端只使用相对路径。Vite 开发代理转发到本地 FastAPI；交付时由 FastAPI 托管前端构建目录。端口通过配置约定，默认后端 8000、前端开发 5173，不把端口写进组件。

## 2. 通用约定

| 项目 | 约定 |
|---|---|
| 格式 | JSON 使用 snake_case；文件上传 multipart，下载使用二进制响应 |
| ID | 不透明字符串，前端不解析前缀、不假定数字递增 |
| 时间 | 带时区的 ISO 8601；服务端返回 UTC，前端按本地时区显示 |
| 成功 | 直接返回业务对象；列表统一 `items`、`total`、`page`、`page_size` |
| 分页 | page 从 1 开始，page_size 默认 20、最大 100；稳定排序 created_at DESC、id DESC |
| 空值 | 明确可空字段返回 null；禁止用空字符串代替尚未存在的版本或错误 |
| 未知字段 | 请求对象拒绝未知字段，防止拼错后静默忽略；前端容忍新增响应字段 |
| 校验 | 前端用于即时提示，后端校验为准；422 不修改数据 |
| 幂等 | 指定的 POST 请求必须带 `Idempotency-Key`，建议 UUID |
| 并发 | 任务写操作携带 `expected_revision`；版本相关动作还携带 `version_id` |

幂等键作用域为 HTTP 方法 + 路径 + 键，后端原子保存请求摘要和业务提交结果。同键同请求返回首次结果，包括同一 Run ID 或版本；同键不同请求返回 409 `IDEMPOTENCY_CONFLICT`；首次请求仍处理时返回 409 `REQUEST_IN_PROGRESS`。网络错误后可使用同键重试；用户明确发起新一次操作时必须换键。前置校验错误不占用幂等键；已经持久化的失败作业仍由原键返回原 Run，新执行使用新键。

幂等记录随本地 Demo 数据保留，不因重启清空。进程中断留下的处理中记录在启动恢复时标为可重试或绑定已提交结果，不能永久返回处理中。业务数据与幂等提交记录使用同一事务；文件导出采用临时文件、原子改名与补偿清理，避免完成记录指向半个文件。

错误示例：

```json
{
  "error": {
    "code": "REVISION_CONFLICT",
    "message": "任务已更新，请重新加载后合并修改",
    "details": {"expected_revision": 3, "current_revision": 4},
    "request_id": "req_demo_01"
  }
}
```

| HTTP | code 示例 | 前端行为 |
|---|---|---|
| 400 | INVALID_FILE、NO_CHANGES | 展示具体原因，保留输入 |
| 404 | NOT_FOUND | 提示对象不存在并刷新入口 |
| 409 | REVISION_CONFLICT、TASK_BUSY、RUN_BUSY、INVALID_STATE、BATCH_ALREADY_GENERATED、IDEMPOTENCY_CONFLICT、REQUEST_IN_PROGRESS | 按 code 呈现冲突或忙碌；禁止自动覆盖 |
| 413 | FILE_TOO_LARGE、CONTEXT_TOO_LARGE | 引导缩减资料 |
| 422 | VALIDATION_ERROR、MODEL_NOT_CONFIGURED、RULE_GATE_FAILED | 标出字段或规则错误 |
| 500 | INTERNAL_ERROR、EXPORT_FAILED | 保留页面内容，提供重试；不得暴露堆栈和凭据 |

作业期间的模型错误存入 Run 的 `error`，GET Run 仍返回 HTTP 200。错误码包括 MODEL_TIMEOUT、MODEL_RATE_LIMIT、MODEL_AUTH_ERROR、MODEL_PROTOCOL_ERROR、MODEL_REQUEST_FAILED、RULE_TOOL_FAILED、RUN_INTERRUPTED。错误 details 只包含允许公开的定位信息，不包含认证头和原始服务商响应。

## 4. 设置、资料与批次

### 4.1 设置

Settings 返回 `api_format`、`base_url`、`generation_model`、`review_model`、`api_key_set`。`api_format` 为 `openai` 或 `anthropic`，旧配置默认 `openai`。PUT 必须包含 `base_url` 和 `generation_model`，省略 `review_model` 时使用生成模型；省略 `api_format` 保留当前格式。`api_key` 可选且 write-only；省略表示保留密钥，空字符串拒绝。两个模型共用同一格式、endpoint 和密钥。支持根地址（补 `/v1`）、带版本或代理前缀的 Base URL（保留原路径）及完整 `/chat/completions` 或 `/messages` 地址（不重复拼接）。保存只验证格式，不调用收费模型，也不声称配置已连通。

密钥输入默认空白，不能把掩码值作为新密钥提交。base_url 限制 http/https，不接受含用户名、密码或 query/fragment 的 URL；允许本地兼容模型服务。已有作业运行时配置更新返回 409 RUN_BUSY，避免操作含义不明确。提示词在后端文件中维护，首版不开放管理接口。

### 4.2 资料

POST multipart 字段名 `file`。支持 UTF-8 TXT/MD/CSV 和无宏 XLSX；5 MiB 上限、解析文本 50,000 字符上限，CSV 最大 20,000 单元格，XLSX 总单元格同样最多 20,000。文件类型、内容和压缩展开规模都由后端检查；不信任客户端 MIME。

CSV 按表头和行转换为可读文本；XLSX 以工作表名、表头、行值呈现。公式单元格、加密文件、不支持编码返回 400 INVALID_FILE，不能返回空内容假装成功。解析完成才创建 Attachment；失败清理本次临时文件。列表仅返回摘要，详情返回 parsed_text 预览。重复上传允许成为不同附件，前端防双击；文件内容不构成指令权限。

### 4.3 创建批次

```json
{
  "name": "居家长任务试跑",
  "goal": "围绕一次真实居家活动设计任务，遵守当前 G2 规则",
  "task_count": 3,
  "task_mode": "long",
  "reference_text": "台面物料包括收纳篮、带拉链的收纳袋、毛巾；按附件中的实际库存设计。",
  "attachment_ids": ["att_demo_01"]
}
```

goal 必填且非空；reference_text 非空或 attachment_ids 至少一项。task_count 1–10，默认 3；task_mode 为 standard / long，默认 long。所有字符串去除首尾空白后校验。附件必须存在；合计资料文本超过 80,000 字符返回 413。批次创建时冻结正文、资料引用内容与规则快照。批次创建不调用模型。

Batch 返回 `task_counts`（所有任务状态计数，包括 0）、`latest_run_id` 和 `can_generate`。前端不自行推导批次总状态。can_generate 仅表示该批尚无任务且无本批活动作业，不代表全局空闲或模型已配置；提交仍由后端检查。

生成请求体为 `{}`。尚未配置模型返回 422；存在任何 queued/running 作业返回 409 RUN_BUSY；已有任务返回 409 BATCH_ALREADY_GENERATED。同键重试首先返回原结果，再判断这些冲突。

## 5. 作业、校验与 AI 审核

Run 字段：`kind` 为 generate_batch / review_task / revise_task；`stage` 为 queued / generating / validating / reviewing / done；`status` 为 queued / running / succeeded / failed / interrupted。stage 表示当前或最后执行阶段，失败时保留该阶段；只有成功置 done。

Run 关联 batch_id、可空 task_id、task_ids，及 progress：total 是本次计划处理的任务数；completed 是已完成处理的数量（含质量退回和技术失败）；failed 是其中技术失败数量。生成整批失败、未形成任务时 completed=0、failed=0，通过 status 和 error 表达失败，不能把它误读为成功。

首次生成要求模型返回完整目标数量、合规结构，整体结构校验后用事务保存全部草稿。随后逐条执行规则校验和 AI 审核。每条处理结束更新进度。存在技术失败则 Run 最终 failed，其余成功记录保留；只有质量退回则 Run succeeded。

ValidationReport 包含 status=passed / failed、issues、checked_at、rule_snapshot_id。issue 包含 code、severity=error / warning、message、可空 step_no 和 rule_id。step_no 从 1 开始。无法定位单步时 null。只有 error 阻断；工具不可用或异常不允许伪造 passed。

Review verdict 为 pass / needs_changes。问题 severity 同样为 error / warning，包含 step_no、rule_id、quote、message、suggestion。needs_changes 必须有至少一个问题；仅有 warning 时归为 pass 并保留建议，pass 不得包含 error。审核模型返回非法结构或引用越界步骤时视为 MODEL_PROTOCOL_ERROR，任务进入 review_failed，不把协议错误当作质量退回。

规则校验问题交给审核 Agent 在一次调用中审查与优化，不直接退回。模型可返回完整 `optimized_task`；正文有变化时复用版本机制保存 `ai_revision`，保留原稿，并重新校验优化正文。Review 绑定最终版本，issues 引用最终正文，summary 说明已优化内容。普通问题直接修复，只有无法修复的严重问题才 needs_changes。最终规则校验通过且 verdict=pass → human_pending；优化后仍有阻断规则或严重问题 → ai_rejected，并保存具体原因。模型连接、协议或执行异常 → review_failed，保留正文供重新审核。

前端轮询 GET Run，每 2 秒一次，终态停止；网络错误显示“状态读取失败”，提供手动重试，不改变真实作业状态。刷新页面通过 Batch.latest_run_id 找回作业；首版没有取消接口，离开页面不取消。

## 6. 任务列表与版本

GET /tasks 参数：batch_id、status、q、page、page_size，均可选；status 只接收一个枚举，q 是对当前标题的字面包含搜索（不把 `%`、`_` 当通配符）。响应额外包含 `status_counts`：应用 batch_id 和 q 过滤、忽略 status 与分页的全部计数。total 则包含 status 过滤。这保证页签计数与当前列表总数意义明确。

TaskSummary 返回标题、step_count、version_no、status、revision、human_edited、busy_run_id 和时间等。TaskDetail 是 summary、current_version、latest_review、last_error、can_decide、ai_review_matches_current_version 的组合；UI 使用这些字段呈现，不依赖自然语言猜测。

当前实现补充 `TaskSummary.batch_comparison`（`similar`、`duplicate` 或 null）和 `TaskDetail.batch_issues`。它们根据同批任务当前版本计算：相似线索只供复核；字面步骤完全相同（不计顺序）属于阻断项。没有其他同批任务时不产生比较结论。

latest_review 是该任务按时间最新的真实 AI 审核，可能属于旧版本。ai_review_matches_current_version 仅在它确实针对当前版本时为 true。human_edited 表示当前稿作者为 human，不表示审核已失效或人工已通过。历史版本和 Review 始终保留。

人工决定历史通过 GET /tasks/{task_id}/decisions 读取，包含版本与驳回理由；刷新后仍能解释任务为什么被人工驳回。不能只在提交成功的临时弹窗中展示理由。

正文结构统一为：

```json
{
  "name": "嘉兴数采-整理出行用品",
  "steps": ["将【收纳篮】放到桌面", "拉开【收纳袋】的拉链"],
  "materials": [{"name": "收纳篮", "quantity": 1}, {"name": "收纳袋", "quantity": 1}]
}
```

这段只演示结构，步数不满足长任务规则，不能当作合格案例。steps 在传输中是字符串数组，不带 `1.` 编号，物料使用【】引用；编号由 UI 和导出添加。material.name 不重复、quantity 为正整数；物料与步骤不一致时校验报告提示，后端不静默改正文。

POST /versions 请求包含 expected_revision、content、change_note。每次提交重新校验；领域规则失败仍允许保存，结构不合法则 422。成功创建新版本，作者 human、父版本为当时 current_version，更新 current_version 和 revision，返回完整详情。无实质正文变化（修改说明变化不算正文变化）返回 400 NO_CHANGES，不制造空版本。

版本列表返回完整 Version 对象数组；每个版本都有自己的校验报告。approved 状态和 busy_run_id 非空时禁止保存。保存不删除历史审核或人工决定，不自动触发模型。

## 7. 决定、重审与重写

三个动作都要求任务无活动作业，并验证 expected_revision。review、revise、decision 的 version_id 必须等于当前版本，否则 409 REVISION_CONFLICT。后端锁定和校验必须在同一事务中，不能先检查再无保护地写入。

| 动作 | 可用状态 | 行为 |
|---|---|---|
| 保存版本 | 除 approved、ai_reviewing 之外的状态，且无作业占用 | 创建 human 新版本，工作流状态不变 |
| 人工通过/驳回 | human_pending | 决定针对当前版本；通过须当前校验 passed |
| 重审 | 除 approved、ai_reviewing 之外的状态，且无作业占用 | 登记作业，置 pending_review，重新校验、审查并按需保存优化版本 |
| 按反馈重写 | 除 approved、ai_reviewing 之外的状态，且无作业占用 | 生成成功后创建 ai_revision 新版本并重审 |

登记重审/重写的占用时立即递增 revision，返回 202 Run。重写期间原状态保留，通过 busy_run_id 禁止并发操作；生成失败释放占用，正文和原状态不变。重写成功将新版本设为 pending_review，随后按规则闸与审核流程更新。所有占用变化及状态/正文写入均递增 revision，前端不能自行加 1，应使用新返回值。

人工决定示例：

```json
{
  "expected_revision": 7,
  "version_id": "ver_demo_02",
  "decision": "reject",
  "reason": "第 8 步把已经备好的用品全部收回，撤销了题目要求的待用终态。"
}
```

decision 为 approve / reject；reject 的 reason 去除空白后至少 1 字，approve 可留空。成功返回 decision 记录及更新后的 task 详情。can_decide 代表流程允许人工决定（human_pending 且空闲），不表示一定可通过；当前 validation.failed 时 approve 返回 422 RULE_GATE_FAILED，reject 仍允许。

人工通过时也会重新检查同批当前版本；存在完全相同的步骤时返回 `RULE_GATE_FAILED`，普通相似提示不阻断。

未保存修改存在时，前端普通“通过/驳回”要求先保存或放弃，不能决定页面上的稿但提交旧版本 ID。保存并通过按蓝图中的两次请求处理。

## 8. 导出

POST /exports 请求包含同一批次的 batch_id 和去重的 task_ids，至少 1 项、最多 100 项。所有任务必须属于该批且 approved，否则 409 INVALID_STATE，整次导出失败，不偷偷跳过。按任务创建顺序输出，不按 UI 选择顺序。

列固定为“任务名字”“任务步骤”“单套所需物料”；步骤每行 `1.xxx`，物料按结构化顺序转成“收纳篮1个、收纳袋1个”。用户/模型内容写为文本单元格，防止 `=`、`+` 等开头内容被当作公式。Export 保存精确 task_id + version_id 清单与 filename，返回相对 download_url；不暴露磁盘绝对路径。

GET download 返回 XLSX MIME 和 Content-Disposition attachment；文件名兼容中文。不存在的记录返回 404；记录存在但文件丢失返回 500 EXPORT_FAILED，用户可新建一次导出。导出不改变 approved 状态，也不回写外部 delivered_tasks 台账。同键重复请求返回原导出；新键可以导出同一组版本，生成新记录。

## 9. 前端 mock 与联调场景

最小 mock 使用 OpenAPI 的字段和枚举，覆盖：

1. 三条不同状态任务、空列表、分页第二页、搜索无结果。
2. AI 原稿 v1 与人工稿 v2；latest_review 仍指向 v1，页面标出版本差异。
3. 保存成功；保存失败保留输入；无改动 NO_CHANGES。
4. 两个页面编辑同一任务，第二次提交 REVISION_CONFLICT。
5. 保存成功但通过失败；展示已保存而非全部失败。
6. 作业处理中禁用操作；后台模型异常与 AI 质量退回分别呈现。
7. 生成已保存草稿、部分审核调用失败；其余任务仍可查看。
8. 重启后 Run interrupted 和对应任务 review_failed；手动重审恢复。
9. 导出已通过版本，拒绝夹带待审任务。

前端 mock 只验证交互。最终必须关闭 mock，用真实服务、同一批次 ID 和可追溯版本跑通，记录哪些模型、规则、导出内容实际验证过。
