# 当前行为契约（0.3.0）

本地双 Agent 工作台：一个生成 Agent、一个审核 Agent、人工终审。SQLite 是任务状态来源。本文定义当前业务语义；请求字段由 [OpenAPI](./openapi.json) 定义，前端响应类型见 `frontend/src/api/types.ts`。旧蓝图和旧接口设计仅供历史参考。

## 生成与资料

生成会话每次发言启动一次生成作业，不是自由闲聊。请求成功表示已入队，不代表模型已成功生成。模型失败保留消息、资料与 Run 错误；可发送新要求，或在失败结果中重试原请求以发起新作业。

`POST /conversations/{id}/messages` 的 `attachment_mode`：

| 值 | 行为 |
|---|---|
| inherit（默认） | 不带附件时继承当前资料；带附件时替换，兼容旧客户端 |
| replace | 用本次列表替换资料，空列表表示清空 |
| append | 与当前资料合并并按 ID 去重 |
| clear | 清空资料；同时提供附件返回 422 |

当前资料最多 20 个附件，作用域仅为当前生成会话。界面显示当前资料并提供预览。资料切换、批次创建、用户消息、Run 入队、幂等结果在一个事务中提交；失败时全部回退。审核会话的附件是待审核任务，不套用生成资料继承。

每个新批次冻结有效附件 ID、解析文本、结构化物料、规则快照。换资料不会修改旧批次。后续生成带全部用户要求、最近 6 条 Agent 回复和最近 30 条当前任务摘要；摘要包含物料与首末步骤，不代表完整历史去重。用户要求不按 400 字静默截断；资料和上下文超过 80,000 字符时明确拒绝，用户需缩减资料或新建会话。

批次允许无资料生成，缺少的库存与现场事实需要人工核验。`task_count=0` 为 Agent 决定条数，`task_mode=auto` 为默认；常规步数 10～20、长任务优先 30 步以上，步数本身不能证明工作量或现场时长。

## 物料快照

CSV 和 XLSX 识别第一行表头。中文模板：

```csv
物品泛化名,类别,总数量,可备套数,初始位置,可夹取,颜色,场景,移动容器
毛巾,布料,10,5,桌面,是,深蓝色,居家,否
```

支持英文别名 `name/category/quantity/available_sets/initial_position/grippable/color/scene/moving_container`。总数量指全部库存，不是单套数量。布尔值支持“是/否”、true/false、1/0。缺失或无效数字保留 null，来源字段保留附件 ID、工作表序号、行号。表格声明不等同于现场已验证。

TXT/MD 与非物料表继续作为资料文本，不虚构结构化库存。重名物料不擅自合并库存。旧附件在升级后不自动重新解析，旧批次不回填新物料；需要时重新上传修订表并新建批次。

## 质量检查

| 等级 | 含义 | 保存草稿 | 人工确认 |
|---|---|---|---|
| error | 明确违规 | 允许 | 阻断，返回 RULE_GATE_FAILED |
| review_required | 需要人工证据 | 允许 | 必须逐项填写依据，否则 REVIEW_REQUIRED |
| warning | 相似线索或建议 | 允许 | 不单独阻断 |

`ValidationReport.status=passed` 仅表示没有 error，不表示现场已验证。审核模型问题仍为 error/warning；模型不能代填人工核验依据。

程序检查已声明物料实例总数不超过 20、已明确移动容器数不超过 2、单套数量 × 5 不超过总库存、可备套数至少 5、物料是否声明不可夹取。没有唯一对应库存、关键字段缺失、用途、初态、终态、现场能力及工作量列为待核验；涉及擦刷时增加清洁依据。

同时在场物品 2～10 件与整个任务涉及物品总数是不同口径；同时在场数量、桌面颜色冲突、抓取稳定性与实际时长由人工现场核验，不以物料表总和替代。花瓶等规则例外应按实际规则填写“移动容器”，不按名称猜测类别。

生成与改写的模型检查、后端保存版本、重审、人工确认和交付导出都使用该边界。旧版本原始校验报告不覆盖；当前任务详情及交付门禁补充当前证据要求，版本列表保留原报告。

## 版本、反馈与确认

任务写操作沿用 `expected_revision`，版本相关操作还需当前 `version_id`；同键重试不重复创建结果。占用期间禁止保存、决定和重审。

| 操作 | 条件 | 结果 |
|---|---|---|
| 保存人工版本 | 除 ai_reviewing 外且未占用 | 新增 human 版本；原 approved/rejected 回 human_pending |
| 重审/重写 | 除 ai_reviewing 外且未占用 | 明确重新处理；完成后重新人工确认 |
| 人工确认/驳回 | human_pending/ai_rejected 且未占用 | 决定绑定当前版本；确认需无 error、无同批完全重复且核验项已处置 |
| 从旧稿恢复 | 与保存相同 | 复制旧内容为新人工版本，父版本是恢复前当前稿，不改历史 |

保存沿用 `change_note`，新增 `change_category`：capability / purpose / terminal_state / wording / materials / duplicate / other。决定同样记录分类；驳回须填写理由。

确认请求的 `resolutions` 是“当前待核验 code → 非空核验依据”的字典，必须覆盖全部当前项且不能夹带无关项，每项最多 2,000 字。证据与决定一起保存，新版本不继承旧确认。历史版本的 AI 意见明确标注，Diff 保留顺序和重复步骤，同时显示任务名、步骤及物料变化。

界面要求逐项勾选，可填写共用说明，并可展开单项说明覆盖。只把当前已勾选且有非空依据的项目映射为 `resolutions`；缺项仍不能确认。界面不默认代勾或代填结论，不改变后端逐项证据契约。

发送失败保留文字、附件、粘贴内容；服务端接受后清空本次输入与选择。会话切换保留本次页面内的草稿。输入法组合期间回车不发送。任务未保存编辑或未提交核验依据离开时提示；保存失败保留内容。

## 导出

`POST /exports` 增加 `intent=draft|delivery`，默认 draft 以兼容旧调用。

- 草稿导出：允许任意状态，文件名及工作表明确标草稿。
- 交付导出：全部任务须为未占用的 approved，最近人工决定须确认当前版本、核验依据完整、无当前 error 或同批完全重复；否则整次拒绝，不跳过任务。

同批限制保留；界面跨批选择会提示重新选择。两种导出均为五列：任务名字、任务步骤、单套所需物料、状态、审核意见。所有单元格强制文本，防止公式注入。导出记录保留 intent 和精确版本清单，选取版本、门禁与记录写入共用事务；文件失败补偿清理。

旧确认无核验记录时不能直接交付，请重新审核并确认。已导出的历史文件不回写、不删除。

## 规则维护与度量

`skills/overrides/` 是项目维护的脚本来源，`skills/snapshot/` 是从上游与 overrides 生成的运行快照：

```powershell
backend/.venv/Scripts/python.exe backend/scripts/sync_skills.py --local
backend/.venv/Scripts/python.exe skills/snapshot/scripts/regression.py
backend/.venv/Scripts/python.exe skills/snapshot/scripts/segment_overlap_regression.py
```

同步先核验并归档旧快照，保留旧批次规则。历史数据文件允许留在本地源目录，但不纳入生效清单、冻结规则或 Agent 文件；回归按清单核验。CSV/XLSX 独立校验复用标准库与已安装 openpyxl，不依赖 pandas；旧 XLS 需另存。

只读统计最近 50 批，不调用模型：

```powershell
backend/.venv/Scripts/python.exe backend/scripts/quality_report.py data/g2tasks.sqlite3 --limit 50
```

数据库实际文件名以 `backend/app/config.py` 为准，也可传入明确路径。统计报告给出规则失败版本比例、已人工决定任务的修改/驳回比例、当前同批重复比例、物料不一致比例、分类及作业耗时。真实模型轨迹记录调用次数与耗时，按批次聚合；旧轨迹和 FakeModel 不伪造调用次数。未采集的人工实际审核时长、现场成功率不计算。反馈仅统计，不自动修改规则。

## 升级与恢复

启动新增 SQLite 字段，不删除、覆盖原任务、附件、版本、决定和导出。首次升级时，新建的会话资料引用字段按该会话最近一个有附件的批次初始化；之后显式清空不会被重复升级还原。旧数据默认无结构化库存、无新证据；仍可查看和导出草稿。此次修复未迁移真实业务库，升级字段在下次正常启动时添加。

需要恢复旧程序时应保留数据备份和新核验记录；旧程序允许任意导出，无法提供本版本的交付门禁。经理 Agent、Swarm、并行编排和自动规则提交仍属于未来方案。
