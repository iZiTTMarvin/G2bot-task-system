# G2 Demo 双人实施清单

> 当前状态：全部待实施。只交付方案，不代表系统已开发。
> 此文件是本目标唯一进度清单；不再另建逐批计划。

## 背景与范围

目标为一个生成 Agent、一个审核 Agent、人工审核与 XLSX 导出的本地闭环。依据：[项目蓝图](./Demo项目蓝图.md)、[接口语义](./前后端接口契约.md)、[机器契约](./openapi.json)。旧完整设计只供背景阅读，不能扩大首版范围。

B 为后端负责人（项目发起人），F 为前端负责人。两人分别维护 `backend/` 和 `frontend/`；B 维护接口基线、Skill 引入与启动脚本，F 发现字段缺口时与 B 同步契约。任何人不覆盖对方无关修改。没有经理、多 Agent 并行、规则自动进化的实施任务。

## 实现依据与待核验前提

- 仓库目前只有设计文档，没有应用源码、依赖锁文件或可运行测试；这里的目录和命令是待创建目标，不是现有实现事实。
- 已核对外部 Skill 存在 `check.py`、`materials.py`、`lookup_history.py`、`export_xlsx.py`、`regression.py` 等脚本，但未验证函数签名与本项目兼容性。B 必须追踪实际输入/输出，包装而非凭文件名假设可用。
- 先固定 Deep Agents 版本并检查默认工具、Skill 文件 backend 与子代理委派暴露方式。只关闭业务不需要的委派能力，不仅靠系统提示词写“不调用”。
- 模型服务商对工具调用、结构化输出、超时的兼容性必须真实验证；先验证一个最小调用，不等 UI 全部完成后才发现不可用。
- 若解析器或 Skill 工具依赖缺失，在明确复用成本后安装最少依赖，并锁版本；不引入额外运行时服务。

## 执行约定

- 开始实施时读取本入口、指定批次及引用材料，核对实际源码和适用规则；只做被授权范围。当前交付为设计，不能据此自动开始实施。
- 一旦另行获得实施授权，按依赖连续推进相应批次；前端 mock 与后端工作可并行，接口和数据语义仍使用同一基线。
- 每批验收与验证完成才勾选；未完成保持空框，并填写已完成内容、阻塞和下一步。
- 技术事实变化就地修正文档；涉及范围或用户行为变化时先同步决定，不能前后端分别加兜底。
- Git 提交、推送、部署、真实重要数据写回另按授权执行；测试使用隔离 data 目录，不改外部 Skill 和历史台账。

## 整体验证与收尾

以下均完成才标记 Demo 可用；耗时超出预期时报告未完成项，不用删掉验收来宣布完成。

- [ ] 真实 3 条任务：生成、规则校验、AI 审核、人工编辑保存、通过/驳回、导出。
- [ ] 原稿保留；AI 审核明确对应版本；已通过版本锁定。
- [ ] 一个模型调用失败、一个 AI 质量退回、一个编辑冲突均能明确呈现并恢复。
- [ ] 重复点击、同键重试和服务重启不会复制任务或永久锁住操作。
- [ ] 上传限制和导出文本安全处理验证完成；仓库与日志无真实密钥。
- [ ] 后端受影响测试、前端 typecheck/build 与实际浏览器检查记录准确命令和结果；未运行项单列。
- [ ] 检查完整改动与工作区，保留无关修改；记录临时文件、未验证范围和已知限制。

建议实施时创建后端命令 `python -m pytest`，前端 scripts `typecheck`、`build`；目前这些命令所需文件尚不存在，不可在交付说明中写成已通过。先跑受影响最小集合，再按实际风险扩大。
